# ZuzuCord Developer Portal

This is a **standalone, Vercel-ready** static site for ZuzuCord developers. Use the `zuzucorddevportal` directory as its Vercel **Root Directory** with framework preset **Other**. Its `vercel.json` serves the static files without a build. The site's source is public, but **the API checks developer role on every privileged action**; hiding a button never grants authorization.

## Initial developer provisioning (admin only)

Developer rights must be granted by the responsible administrator in the Zuzify Supabase SQL editor. Do not use a public signup field, profile flag, hardcoded PIN, or client-side variable.

```sql
-- Replace only this placeholder with your own existing ZuzuCord username.
insert into public.zuzucord_user_roles (user_id, role)
select user_id, 'developer' from public.zuzucord_accounts
where username = 'REPLACE_WITH_YOUR_USERNAME'
on conflict(user_id, role) do nothing;
```

No account is granted developer access automatically through this website. To revoke a developer, use the privileged SQL editor. The developer site can grant/revoke **verified** and **beta_tester** badges but cannot elevate another account to **developer**.

## Bot applications

The developer portal creates ZuzuCord bot apps (not Discord applications), issues one-time `zcb_...` tokens, and revokes or rotates those tokens. New tokens are generated by the Supabase Edge Function `zuzucord-bot-api`, which checks the authenticated developer account **on the server**, then stores **SHA-256 hashes** in the RLS-protected `zuzucord_bot_keys` table. The plain token is returned **once**. Never commit tokens or distribute them to browsers.

Server owners must install an approved bot app into their own server through the Windows client before the bot can send messages.

Example API call made **from a bot's server**, not a frontend website:

```http
POST https://wfqudstuncdldsvxqveu.supabase.co/functions/v1/zuzucord-bot-api
Content-Type: application/json
X-ZuzuCord-Bot-Token: zcb_YOUR_TOKEN

{"action":"send","channel_id":"UUID","content":"Hello from ZuzuCord bot"}
```

The backend checks the token hash, revocation status, bot installation, and channel. It limits messages to 1500 characters, one per 3 seconds and 200 per bot per UTC day.

## Official ZuzuCord account

Developers can publish **read-only platform announcements** using `zuzucord_publish_announcement`. This is a single global announcements feed shown to every signed-in user, not a mass-DM system or spam bot. A platform-wide 30-minute cooldown limits broadcasts. Users may view but cannot reply, edit or send official messages.

## ServerBoostCredits

Developers issue free nonmonetary Crystals through `zuzucord_grant_crystals`. The developer portal resolves usernames to existing ZuzuCord accounts and records grants. Legacy ServerBoostCredits remain valid at 100 Crystals per boost. Both currencies have no monetary value and cannot be purchased or transferred. The secure `zuzucord_issue_boost_credits` RPC checks the developer role, and `zuzucord_boost_server` checks membership and a wallet balance before spending a credit. Each level adds 10 community channels; levels 1–3 expand capacity from 30 to 40, 50 and 60.

## User roles

Every registered account is a regular **user** by default. Extra role records may label accounts **verified**, **beta_tester**, or **developer**. The app displays verified badges and role labels. Do not treat a client-provided role value as proof of permission.

## Production website sync

`website/sync.html` allows any registered account to sync app appearance and home-server settings through `zuzucord_user_sync` with user-specific RLS. The separate `beta-website/sync.html` keeps its older tester-only experiment.

## Status

The portal code and database/RPCs are committed and deployed to Supabase; its **Vercel website has not been deployed** in this workflow. Live bot requests and multi-user role/credit UX require acceptance tests on deployed sites. The project is still a preview.

## Crystals for server perks

The portal's **Grant Crystals** form replaces the old credit-issuing form. Developers can grant up to 1,000 at once; the Windows app shows Crystal history and allows members to spend 100 on each permanent boost. See `desktop-react/README.md` for unlocks and compatibility rules. Only server owners can change unlocked server branding.
